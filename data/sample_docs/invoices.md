# Invoices

An invoice itemizes what a customer owes for a billing period. Most invoices are generated automatically by [subscriptions](subscriptions.md); you can also create one-off invoices directly.

## The invoice object

```json
{
  "id": "inv_8kQ2mVx",
  "object": "invoice",
  "customer": "cus_3nXp7Kd9",
  "subscription": "sub_9wF4tBn2",
  "status": "open",
  "currency": "usd",
  "subtotal": 8700,
  "tax": 741,
  "total": 9441,
  "amount_due": 9441,
  "lines": [
    {
      "description": "Team plan, 3 seats, Jun 1 to Jul 1",
      "price": "prc_5sRj2Xa8",
      "quantity": 3,
      "amount": 8700
    }
  ],
  "due_date": "2026-06-15T00:00:00Z",
  "created": "2026-06-01T00:00:00Z",
  "livemode": false
}
```

Amounts are integers in the smallest currency unit. `total` is `subtotal` plus `tax`; `amount_due` is `total` minus applied [credit notes](credit-notes.md) and partial payments.

## Invoice statuses

| Status | Meaning |
|---|---|
| `draft` | Editable. Line items can be added or removed. Not yet visible to the customer. |
| `open` | Finalized and collectable. Immutable except for payment and credit notes. |
| `paid` | `amount_due` reached zero. Terminal. |
| `void` | Canceled before payment. Terminal. |
| `uncollectible` | Written off after failed dunning. Terminal, but can still be paid. |

Subscription invoices are created as `draft`, then finalized automatically one hour later. The delay is a grace window for your integration to add line items, such as metered usage corrections.

## Create an invoice

`POST /v1/invoices`

Creates a `draft` one-off invoice.

| Parameter | Required | Description |
|---|---|---|
| `customer` | yes | ID of the customer to bill. |
| `lines` | yes | Array of `{description, amount, quantity}` or `{price, quantity}`. |
| `due_date` | no | Defaults to 14 days after finalization. |
| `auto_collect` | no | Boolean, default `true`. If `true`, Meridian attempts payment with the customer's default payment method on finalization. |

## Finalize an invoice

`POST /v1/invoices/{id}/finalize`

Moves a `draft` invoice to `open`, assigns the sequential invoice number, calculates [tax](tax.md), fixes the totals, and fires `invoice.finalized`. Finalizing a non-draft invoice returns `422` with code `invoice_not_draft`. Finalization is the point of no return: after it, amounts can only be adjusted with a credit note.

## Void an invoice

`POST /v1/invoices/{id}/void`

Voids an `open` invoice, halting collection permanently. Use void for invoices issued in error before any payment. If the customer already paid part of the invoice, do not void it; issue a [credit note](credit-notes.md) for the remainder instead. Voiding a `paid` invoice returns `422`.

## List invoices

`GET /v1/invoices`

Supports the standard [pagination parameters](pagination.md#pagination-parameters) plus:

| Filter | Description |
|---|---|
| `customer` | Only invoices for this customer ID. |
| `status` | One of the five statuses. |
| `subscription` | Only invoices generated by this subscription. |
